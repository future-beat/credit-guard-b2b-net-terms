# Quick task 260822-2h1 — fix `sourceWithoutComments` phantom block-comment defect

## Problem

`tests/helpers/module-source.ts` strips BLOCK comments before LINE comments. A
`/*`-like sequence inside a `//` comment (the glob `` `/app/*` `` in
app/routes/app.tsx) opens a phantom block comment that swallows code until the
next `*/`. Source guards then pass against (near-)empty strings. Found by the
06-04 executor, which worked around it by rewording its comment.

## Tasks

1. Replace the regex pair with a single-pass tokenizer (`stripComments`) that
   tracks string literals, template literals (incl. `${}` nesting), regex
   literals (heuristic), line comments and block comments — so no comment
   delimiter inside any other token can open or close a comment. Add
   `tests/helpers/module-source.test.ts` covering: glob in line comment,
   `//` inside a string literal, `/*` inside a template literal,
   nested-looking sequences, and the real `app/routes/app.tsx` file.
2. Audit every consumer (scheduler, reminders, settings-messages,
   graphql-error-surfacing tests) and add a non-triviality sanity assertion
   on the stripped source at each call site.
3. Run `npm test`; any guard that now fails is a real finding — report, do
   not weaken.
