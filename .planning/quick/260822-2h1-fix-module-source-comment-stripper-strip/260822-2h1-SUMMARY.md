# 260822-2h1 — `sourceWithoutComments` phantom block-comment fix

## What changed

- `tests/helpers/module-source.ts`: the regex pair (block-then-line) is
  replaced by `stripComments`, a single-pass tokenizer that respects
  single/double-quoted strings, template literals (with nested `${}`),
  regex literals (heuristic), line comments and block comments. Comment
  delimiters inside any other token can no longer open or close a comment.
  Trailing `// ...` comments are now stripped too (the old helper only
  matched line-start comments).
- `tests/helpers/module-source.test.ts` (new, 9 tests): glob-in-line-comment
  (the 06-04 defect), `//` in string literal, `/*` in template literal,
  nested-looking sequences, regex literals, escaped quotes, unterminated
  block, plus real-file checks on `app/routes/app.tsx` and every guarded
  module.
- Sanity assertions added at every `sourceWithoutComments` call site
  (scheduler, reminders, settings-messages, graphql-error-surfacing tests):
  a length floor and/or an anchor string only the real module satisfies.

## Findings

- Old-vs-new comparison over all 34 tracked `app/`, `extensions/`, `tests/`
  sources: the only divergences are trailing `//` comments the old helper
  kept (ledger.server.ts, the helper itself). No guarded file was blanked on
  this branch — the glob comment that triggered the defect lives in 06-04's
  `app/routes/app.tsx`, which is not on this branch — so **no guard flipped
  from pass to fail**. Guards were not weakened.
- Known limitation (documented in the helper): `//` in bare JSX text is
  treated as a line comment.

`npm test`: 23 files, 597 tests passed (588 → 597). `tsc --noEmit` and
eslint clean on touched files.
