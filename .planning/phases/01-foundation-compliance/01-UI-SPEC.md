# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (from CONTEXT.md):** embedded Polaris admin SHELL only — install/OAuth landing, app frame + navigation skeleton, empty-state home page, and route-level error handling. No feature UI (credit settings arrive Phase 3, AR dashboard Phase 6). This contract locks the design-system foundations those later phases inherit.

**Governing principle:** Phase 1's entire UI risk is *diverging from Polaris*. The contract below is therefore mostly a set of prohibitions: consume Polaris web-component defaults, never restyle them. Every custom CSS declaration is a potential app-review liability (LNCH-03).

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none — shadcn not applicable | CLAUDE.md + 01-RESEARCH.md: Polaris web components mandated for embedded Shopify admin; `@shopify/polaris` React explicitly deprecated/forbidden |
| Preset | not applicable | — |
| Component library | **Polaris web components** (`s-page`, `s-section`, `s-text`, `s-button`, `s-banner`, `s-stack`, `s-box`, …) loaded via the App Bridge CDN script (auto-latest, no npm version) | CLAUDE.md stack table; RESEARCH.md Standard Stack |
| Icon library | Polaris icons as exposed by the web components (icon attributes/slots). No third-party icon package. | Default — consistent with Polaris mandate |
| Font | Inter (Shopify admin default), inherited from the Polaris CDN styles. **Never load a custom font.** | Default — Polaris admin design language |
| Dark mode | Not implemented — Shopify admin controls theming; components adapt via CDN tokens. No app-side theme code. | Default |

**Hard rules for the executor:**
1. All admin markup uses `s-*` Polaris web components inside React/JSX — never `@shopify/polaris` React imports (deprecated; app-review trap per PITFALLS reference in CONTEXT.md).
2. App Bridge CDN `<script>` in the document head (template default) — this is what satisfies the "latest App Bridge" review check; do not pin or self-host it.
3. Custom CSS is limited to layout glue the components cannot express. Zero custom colors, font sizes, font families, or shadows.
4. Verify exact web-component tag names against the live App Bridge/Polaris web-components docs (shopify.dev/docs/api/app-home/web-components) at scaffold time — the catalog is CDN-versioned and this contract's tag names are indicative, not load-bearing.

## Spacing Scale

Declared values (all multiples of 4; these are the Polaris space-token steps — consume them via component props like `gap`/`padding` on `s-stack`/`s-box`, never hand-written margin CSS):

| Token | Value | Polaris token | Usage |
|-------|-------|---------------|-------|
| xs | 4px | space-100 | Icon-to-label gaps, inline padding |
| sm | 8px | space-200 | Compact element spacing within a row |
| md | 16px | space-400 | Default gap between elements in a card/section |
| lg | 24px | space-600 | Section internal padding, card gutters |
| xl | 32px | space-800 | Gap between page sections |
| 2xl | 48px | space-1200 | Major section breaks |
| 3xl | 64px | space-1600 | Vertical centering breathing room on the empty-state page |

Exceptions: none. Phase 1 has no touch-target exceptions (desktop admin iframe; Polaris components already meet minimum hit areas).

## Typography

Polaris admin design language defaults, delivered by the web components. Declared here for audit reference — the executor selects these via component variants (`s-text`, `s-heading` levels), **never** via CSS `font-size`/`font-weight`.

| Role | Size | Weight | Line Height | Delivered by |
|------|------|--------|-------------|--------------|
| Body | 13px | 450 (regular) | 1.5 (20px) | `s-text` default / body-md variant |
| Label / meta | 12px | 450 (regular) | 1.33 (16px) | small/subdued text variant |
| Heading (card/section) | 14px | 650 (semibold) | 1.43 (20px) | section/card heading variant |
| Display (page title) | 20px | 650 (semibold) | 1.2 (24px) | `s-page` title |

Contract: exactly 4 sizes (12, 13, 14, 20), exactly 2 weights (450 regular, 650 semibold). If the live CDN tokens differ by a pixel from these reference values, the CDN wins — the invariant is "component variants only, no custom type CSS," not the literal pixel numbers.

## Color

Polaris tokens only, consumed via component `tone`/`variant` props. Hex values below are the current Polaris defaults, listed for audit reference — **never hardcode a hex in app code.**

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Polaris app background (`--p-color-bg`, ref #F1F1F1) | Page background behind all content — supplied automatically by `s-page` |
| Secondary (30%) | Polaris surface (`--p-color-bg-surface`, ref #FFFFFF) | Cards, sections, the empty-state container |
| Accent (10%) | Polaris primary action (near-black primary button fill, ref #1A1A1A) + interactive link blue (ref #005BD3) | See reserved-for list below |
| Destructive | Polaris critical tone (ref #8E1F0B text on critical surface) | Destructive actions only — **none exist in Phase 1** |

Accent reserved for:
- The single primary button on any given page (Phase 1: only the error-state "Reload page" button)
- Hyperlinks inside banner/body copy (e.g., support link in the error banner)

Explicitly NOT accent: navigation items, headings, badges, the empty-state illustration area. Phase 1 pages are intentionally neutral — the first strong accent moment belongs to Phase 3's "Set credit limit" CTA.

Semantic tones (info/success/warning/critical) come only from Polaris `s-banner`/badge tone props. Phase 1 uses at most: `critical` (error boundary banner), `info` (optional deploy-environment notice — omit unless needed).

## Layout & Navigation Contract

Locked here because Phases 3 and 6 inherit this frame.

| Element | Contract |
|---------|----------|
| App frame | RR7 `app.tsx` layout (template default) rendering inside the Shopify admin iframe; App Bridge provides the outer chrome. The app never draws its own top bar or global header. |
| Page shell | Every route renders one `s-page` with a `title`. Phase 1 home title: **"Credit Guard"**. Single-column layout; no sidebars (Shopify admin nav owns lateral navigation). |
| App navigation | App Bridge nav menu (template's `ui-nav-menu` / current nav web component). **Phase 1 renders exactly one item: "Home."** Do not render placeholder links to routes that don't exist. |
| Reserved nav taxonomy (future phases — do not build now) | "Home" (Phase 1 →becomes dashboard in Phase 6), "Companies" (Phase 3 credit settings), "Settings" (Phase 4 block-message editing, Phase 5 reminders). Locked so later phases don't rename Phase-1 labels out from under merchants. |
| Content width | Polaris page default width; no custom max-width CSS. |
| Focal point (home) | The empty-state heading "Credit Guard is installed" is the home page's visual anchor — the eye lands there first. Do not add an illustration, badge, or graphic to fill the anchor role. |
| Loading | Server-rendered RR7 routes — no client-side data fetching in Phase 1, so no skeleton states needed. App Bridge's built-in navigation loading indicator covers route transitions. Do not add spinners. |

## Copywriting Contract

Tone (locked for all phases): calm, factual, merchant-facing B2B. Sentence case everywhere (Polaris standard). No exclamation marks. Buttons are verb-first. Say "companies" (Shopify's B2B term), never "clients." Say "net terms," never "NET30." Never overpromise features that aren't built.

| Element | Copy |
|---------|------|
| Primary CTA | None in Phase 1 (shell has nothing to configure — honest by design, mirrors CRED-04 observe-only stance). Error-state action button: **"Reload page"**. First feature CTA is reserved for Phase 3: "Set credit limit". |
| Empty state heading (home) | **"Credit Guard is installed"** |
| Empty state body (home) | **"Your accounts receivable dashboard will appear here. Credit Guard hasn't changed anything in your store — companies check out exactly as they do today until you set a credit limit."** |
| Error state (route ErrorBoundary, critical banner) | Heading: **"Credit Guard couldn't load"**. Body: **"Reload the page to try again. If this keeps happening, contact support."** Action: "Reload page" button (primary). ("Contact support" becomes a mailto link once the D-04 domain exists; plain text until then.) |
| Destructive confirmation | None — Phase 1 has no destructive actions in the app UI (uninstall happens in Shopify admin, outside our surface). |

Page title: "Credit Guard" (`s-page` title on home). The document `<title>` follows the same string (App Bridge/admin handles outer tab title).

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Probe run 2026-08-17 (post-verification, engine-computed over 4 elements: home page, error banner, nav menu, route transitions): 24 applicable considerations — 6 resolved explicit, 4 resolved backstop, 14 dismissed with reasons, 0 unresolved.

**Resolved (verification: explicit) — truths for the planner:**

- Home page renders the documented empty-state copy (Copywriting Contract rows 2–3) on every load — in Phase 1 the empty state IS the page; there is no populated variant
- Home page loading is server-rendered; App Bridge's built-in navigation indicator is the only loading affordance — the contract forbids app-drawn spinners (Layout Contract "Loading" row)
- Any route failure (auth, loader, render) renders the documented critical banner via the `app.tsx` `ErrorBoundary` (Copywriting Contract row 4); unauthenticated/expired-session requests are redirected by the library, not rendered
- The error state itself is fully specified: heading, body, and a primary "Reload page" retry action (Copywriting Contract row 4)
- Route transitions show App Bridge's built-in loading indicator only (no skeletons, no spinners)
- Route-transition failures land in the same `ErrorBoundary` — one error path for all Phase 1 routes

**Resolved (verification: backstop) — held-out visual checks:**

- { statement: "Home-page literals ('Credit Guard', 'Credit Guard is installed', body copy) show no truncation in the admin iframe at default widths — visual UAT on the dev store", verification: backstop }
- { statement: "Error-banner copy wraps (not clips) inside the Polaris critical banner at narrow admin widths — visual UAT on the dev store", verification: backstop }
- { statement: "App Bridge nav menu registers and renders the single 'Home' item on the dev store; app remains usable if nav registration fails", verification: backstop }
- { statement: "Nav label 'Home' renders without truncation — visual UAT alongside the home-page check", verification: backstop }

**Dismissed (not applicable in Phase 1, with reasons):**

- populated / partial / zero-one-many / overflow on the home page — Phase 1 renders no data-bearing content or collections; these categories become real considerations in Phase 6's dashboard UI-SPEC
- populated / partial / zero-one-many / empty / overflow / long-text on the nav menu — exactly one fixed literal item; no data shapes the nav until Phase 3
- loading on the error banner — the `ErrorBoundary` renders synchronously; there is no loading state for an error boundary
- loading on the nav menu — App Bridge owns nav rendering; the app cannot draw a nav loading state
- overflow / long-text on route transitions — transitions render no app-drawn content
