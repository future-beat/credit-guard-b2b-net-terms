## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> Railway edge -> app server | TLS terminates at Railway; app trusts PORT/env injection from platform |
| App server -> Sentry | Error telemetry leaves our infrastructure — content control is on us |
| Local machine -> Railway/Sentry/registrar dashboards | Credentialed human/CLI sessions configure production |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Information disclosure | SHOPIFY_API_SECRET / SENTRY_DSN handling | high | mitigate | Secrets live only in Railway service variables (API secret as sealed) and gitignored .env; acceptance criteria assert no committed values; never echoed to logs |
| T-01-07 | Information disclosure | Sentry event payloads | medium | mitigate | Default-PII option stays disabled; no request bodies/webhook payloads attached to events (Task 1 negative gate); primary boundary because telemetry crosses infrastructure |
| T-01-08 | Tampering | DNS/domain takeover of app.<domain> | medium | accept | Registrar account is user-controlled with its own auth; Railway TXT verification proves ownership; residual registrar-account risk is the user's credential hygiene — documented, not app-controllable |
| T-01-09 | Spoofing | Debug error route abuse | low | mitigate | debug.sentry-check.tsx sits behind authenticate.admin and is deleted within the same task after verification (file-absence gate) |
| T-01-SC | Tampering | npm installs (@sentry/react-router, @railway/cli — postinstall binary fetch) | high | mitigate | Both approved in plan 01-01 Task 1 blocking-human legitimacy checkpoint; lockfile-resolved versions recorded in SUMMARY |
</threat_model>
