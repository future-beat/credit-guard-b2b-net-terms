## Gap record (authoritative — read before any edit)

From 02-05-SUMMARY.md § CRITICAL FINDING, verified live on 2026-08-19:

- `Order.purchasingEntity` requires `read_customers`. The CF-1 scope set (`read_orders,read_all_orders,read_payment_terms,read_companies`) deliberately excludes it. Shopify returns the field as null on EVERY order — bulk AND normal queries — alongside an explicit GraphQL error (`extensions.requiredAccess: read_customers access scope`).
- Adding `read_customers` is REJECTED (LOCKED): it pulls PII the app never needs, risks PCD Level 2, and contradicts the published privacy policy.
- VERIFIED WORKING on the live shop with current scopes: `company(id){ orders(first:N){ id name displayFinancialStatus totalOutstandingSet{shopMoney{amount currencyCode}} paymentTerms{ paymentTermsType paymentSchedules{ dueAt completedAt } } } }` and `companies(first:N){ edges{ node{ id name ordersCount{count} } } }`.
- Independent second defect: an ACCESS_DENIED that Shopify explicitly returned was indistinguishable from "this order has no company". The bulk JSONL path has NO errors channel at all (field denials arrive as silent nulls in JSONL), so the only structural protections are (a) never selecting a field outside the granted scopes, and (b) loud, centralized errors[] surfacing on every non-bulk response.

**D-03 note:** D-03's intent — identity keys to the Company, NEVER to the order's buyer-contact — is unchanged and still guarded. Only the mechanism changes: the authenticated company→orders edge replaces the purchasingEntity union, because the latter is scope-trapped. Rewrite the ledger.server.ts header rule 2 to say exactly this.
