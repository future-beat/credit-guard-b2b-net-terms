> API Coverage Decision Checkpoint artifact. Enumerates the capability surface Phase 3 integrates.
> INTEGRATE is the default; every OPT-OUT carries a one-line reason.
> Extends the Phase 2 matrix (.planning/phases/02-ar-ledger-credit-engine/COVERAGE.md) — this file covers only Phase 3's new surface.

| capability | decision | reason |
|---|---|---|
| `metafieldsSet` on Company (`$app`/`credit_v1`, type json) | INTEGRATE | CRED-03 — the ONLY server↔Function interface; single JSON snapshot, atomic per call (plan 03-01) |
| `MetafieldsSetInput` userErrors surface (`code`, `elementIndex`) explicit check | INTEGRATE | userErrors arrive inside `data` with empty `errors[]` — graphqlJson alone cannot see them (Pitfall 1) (plan 03-01) |
| OAuth scope: `write_companies` | INTEGRATE | metafieldsSet requires the owner-type write scope — no metafield-specific scope exists; the ONLY new scope for Phases 3+4 (plan 03-02) |
| TOML declarative definition `[company.metafields.app.credit_v1]` | INTEGRATE (A1-gated) | Contract-home #1: version-controlled, auto-created on deploy, `access.admin = "merchant_read"` for support visibility (plan 03-02) |
| `metafieldDefinitionCreate` (ownerType COMPANY) | INTEGRATE as fallback only | Schema-verified escape hatch if the TOML `company` owner-type token is rejected at deploy (A1) — executed only on rejection (plan 03-02) |
| `$app` reserved-namespace shorthand (literal, never `app--{id}`) | INTEGRATE | Platform resolves it per-app; the long form is unsupported in some surfaces and couples code to the client id (plans 03-01, 03-05) |
| `Company.metafield(namespace, key)` read-back query | INTEGRATE | Roadmap gate: contract verifiable on real Company records before Phase 4; readable under existing read_companies (plan 03-05) |
| Hash-skip change detection (sha256, node:crypto) | INTEGRATE | Bounds hourly sweep republish to genuinely changed payloads — no-op writes cost zero API points (plans 03-01, 03-04) |
| `compareDigest` optimistic-concurrency on metafieldsSet | OPT-OUT | App is the sole writer of its `$app` namespace by platform rule — a read-before-write round trip guards against a race that cannot occur |
| Multiple typed metafields (money limit, boolean overdue, …) | OPT-OUT | Multi-key reads are non-atomic at checkout (torn state); `money` type cannot express D-02 null-vs-0; one json snapshot wins (research Alternatives) |
| `metafieldsDelete` on limit removal / uninstall | OPT-OUT | Removal publishes `limit: null` (observe-only) — the metafield always exists once published; uninstall cleanup is platform-side (definitions deleted, values retained/reassociated per Shopify staff) and shop/redact already covers app data |
| Metafield definition pinning/management UI | OPT-OUT | Definition is machine-read contract law; `merchant_read` gives visibility — merchant editing is explicitly excluded (app is sole writer) |
| CompanyLocation metafields | OPT-OUT | Ledger is company-keyed (Phase 2 D-03); location granularity is a v2 concern |
| App-data metafields on AppInstallation | OPT-OUT | Scope-free but useless here — the Phase 4 Function reads Company metafields via purchasingCompany |
| `$app:suffix` sub-namespaces | OPT-OUT | One app, one credit contract — suffixes add nothing (research Reserved Namespace) |
| Batched metafieldsSet (25/call chunking) | OPT-OUT for now | Publishes are per-company on change; the sweep backstop is hash-skip-bounded sequential — chunking matters only at fleet sizes far past ICP (revisit if a bulk-republish task ever appears) |
| Metafields Storefront/checkout access grants (`access.storefront`, checkout UI-extension grants) | OPT-OUT | Function input queries need no grant for the parent app's `$app` metafields (A2) — Phase 4 empirically gates this; UI-extension grant regime does not apply |
