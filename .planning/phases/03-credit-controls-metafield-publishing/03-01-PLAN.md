## Phase Goal

**Goal (prose, carried verbatim from ROADMAP):** Merchant can configure per-company credit, and each company's credit state is published where checkout can read it.

## Locked Decisions (planner locks, per research Open Questions)

- **L-01 (D-04 interpretation):** `data_complete` is **shop-scoped** — `false` iff any LedgerOrder in the shop has `attributionStatus = "UNRESOLVED"` AND `hasPaymentTerms = true`, applied to every company's payload. Rationale: UNRESOLVED rows carry `companyId: null` by construction (verified ledger.server.ts:657–678), so "the company has an UNRESOLVED order" is unrepresentable per-company; an unattributed net-terms order could belong to any company. NO_COMPANY (proven none) and D2C UNRESOLVED without payment terms never flag it. Field name, type, and Phase 4 read semantics unchanged — this is an interpretation, not a contract change.
- **L-02 (republish fan-out):** when shop-scoped data_complete flips, other companies' payloads heal via the hourly sweep publish backstop (plan 03-04) — hash change forces the write; hash-skip bounds the burst to genuinely changed payloads (≤50 companies/shop worst case). No inline fan-out: the stale direction is conservative (false lingering up to an hour, never a phantom true).
- **L-03 (serialization precision):** limits enter through grammar `^\d{1,13}(\.\d{1,2})?$` (max 2dp — reject, never round or coerce); serialization is `Prisma.Decimal.toFixed(2)` (ROUND_HALF_UP if a 4dp ledger value ever occurs; store-currency ledger amounts are 2dp by construction so no rounding occurs in practice). This is the contract's rounding law.
- **L-04 (currency source):** `currency` = currencyCode of the company's own ledger rows; else the shop's most recent LedgerOrder; else JSON null (shop with zero ledger rows). All amounts are store currency by D-07, so null currency can only co-occur with exposure "0.00".
