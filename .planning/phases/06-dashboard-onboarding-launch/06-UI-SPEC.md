# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (from 06-CONTEXT.md):** the merchant-facing launch surfaces: (1) the **AR dashboard** replacing the Phase 1 placeholder home (`app/routes/app._index.tsx`), (2) the **guided setup** block (3 steps, D6-03), (3) the **credit-hold feed + reminder activity** (D6-02 vocabulary), (4) the **review-prompt** moment (LNCH-02 — timing only; Shopify draws the modal), and (5) the **billing gate** (D6-01 — a `_top` redirect; the only copy of ours is the fail-open path, which renders the normal app). No new tables; one additive `Shop` migration (`onboardingReviewedAt`, `onboardingDismissedAt`, `reviewPromptedAt`).

**Governing principle (inherited):** this contract **extends** 01-UI-SPEC.md and 03-UI-SPEC.md — same design system, spacing, typography, color tokens, copy voice. Deltas only. The Phase 1 hard rules and the Phase 3 additions apply verbatim (see Hard Rules below).

**This page is the App Store hero screenshot AND the BFS 4.2.3 "is the app set up and working?" surface.** A populated dashboard with 2 of 3 setup steps done, one company on credit hold, and a short feed is the marketing shot — every state below must look intentional.

## Hard Rules (inherited + Phase 6)

1. Polaris `s-*` web components only, inside React/JSX. Never `@shopify/polaris` React imports.
2. App Bridge CDN script as rendered by `AppProvider` (template default) — do not pin, self-host, or move it.
3. Custom CSS limited to layout glue the components cannot express. Zero custom colors, type, shadows. **Phase 6 target: zero custom CSS at all** — `s-grid`, `s-stack`, `s-box`, `s-section` cover every layout need below.
4. **Live catalog wins over this spec.** Tag names, prop names, tone enums, and icon names below were checked against `@shopify/polaris-types@1.0.1` on 2026-08-21 (`ToneKeyword = auto|neutral|info|success|caution|warning|critical|accent|custom`; `s-banner` tone = `auto|critical|warning|success|info`; `s-icon` tone excludes `accent/custom`). **Verify every element against the live catalog at execution.** If a component or prop is missing at runtime, compose from primitives; never add a dependency.
5. **Components that DO NOT exist — do not plan for them:** `s-setup-guide`, `s-progress`, `s-progress-bar`, `s-empty-state`, `s-card`, `s-index-table`, `s-data-table`, `s-resource-list`, `s-callout-card`, `s-stat`. No charts library, no sparklines — text and tables only.
6. No new npm dependencies. No upgrade of `@shopify/shopify-app-react-router` (stay on 1.2.x).
7. Shop-scoped data only: every dashboard query is `where: { shop }` from `authenticate.admin(request).session.shop`. Never a cross-shop aggregate, never a query keyed on a client-supplied shop.
8. **Honesty rule (extends Phase 3):** every number on the dashboard must be provable from a ledger row. No estimated totals, no "blocked $X", no "saved you $X". "Credit hold" is the vocabulary for `blockedState`; the word "blocked" appears only in the existing Settings page copy about the checkout rule.
9. Money is never computed in floating point on the server; display formatting uses the existing `createMoneyFormatter` (lift from `app.companies.tsx` into a shared module — do not duplicate). Currency comes from `resolveShopCurrency` (most recently refetched `LedgerOrder.currencyCode`); null currency → decimal format with no symbol, never a guessed `$`.
10. Upcoming-due amounts come from per-row `LedgerOrder.outstandingShop`; `LedgerSchedule` money columns are NEVER summed (schema contract). Bucket totals are sums of `outstandingShop` over distinct orders, computed as Decimal strings server-side.

## Color

Inherited from 01-UI-SPEC.md: Polaris tokens only via `tone`/`variant`/`background` props, zero hex in app code. 60% app background (`s-page`), 30% surfaces (`s-section` / `s-box background="subdued"` for KPI tiles if needed — verify prop), 10% accent.

**Accent reserved for (complete list for the dashboard):**
- **At most one `variant="primary"` button on the page**, chosen by setup state, in this order of precedence: the current (first incomplete) setup step's action button while the guide is visible → none once the guide is dismissed. The dashboard has no primary action after setup; it is a reading surface.
- Hyperlinks in section headers / banner copy ("View companies", "Open settings", order links) — interactive link blue via `s-link`.

Explicitly NOT accent: KPI values, badges, table headers, the feed, the dismiss button, secondary step buttons (`variant="secondary"`).

**Semantic tone map (the whole phase — nothing else may carry a tone):**

| Tone | Used for |
|------|----------|
| `critical` | "Overdue" badge (ledger fact); "On credit hold" badge; route ErrorBoundary banner (inherited) |
| `warning` | "Over limit" badge; **bypassed-order alert banner** (orders slipped past a hold in the last 30 days) |
| `caution` | "Enforcement bypassed" badge (Phase 3 lesson: no `attention` tone exists) |
| `info` | backfill / balances-incomplete banner; reminders-off notice; currency-mismatch notice |
| `success` | **Exactly one use:** the `s-icon type="check-circle-filled" tone="success"` on a completed setup step. No success badges, no success banners on the dashboard. |
| `neutral` | feed "kind" badges for non-alarming transitions ("Released", "Bypass on", "Bypass off") |

Never color a number. Severity lives only in badges and banners.

## Layout & Navigation Contract

### Navigation (BFS 4.1.4)

| Element | Contract |
|---------|----------|
| Nav menu | **Remove `<s-link href="/app">Home</s-link>`.** Final `s-app-nav`: **Companies** (`/app/companies`), **Settings** (`/app/settings`). The app name in the admin sidebar IS the link to `/app`; a second "Home"/"Dashboard" item is BFS rejection reason 4.1.4 #3 ("a separate navigation item in addition to the app name that redirects to the app's homepage"). **Decision: no explicit dashboard item, no rename.** Rationale: a "Dashboard" label is still "a separate navigation item that redirects to the homepage" — renaming does not cure it. The dashboard is findable by clicking the app name, which is the admin convention merchants already use. |
| Phase 1 reserved taxonomy | "Home" slot retired (this phase). "Companies" and "Settings" labels unchanged. Update the code comment in `app.tsx` to cite this contract. |
| Page title | `s-page heading="Credit Guard"` — unchanged from Phase 1 so the tab/app name and page title agree. Not "Dashboard". |

### Page structure (top → bottom, single column)

```
s-page heading="Credit Guard"
├── [Banner slot — at most ONE banner, by precedence below]
├── [Setup guide s-section — only while onboardingDismissedAt == null]
├── KPI row: s-grid (4 tiles)
├── s-section "Overdue companies"          (table, or empty line)
├── s-section "Due in the next 30 days"    (table, or empty line)
├── s-section "Credit holds and bypasses"  (feed table, or empty line)
└── s-section "Payment reminders"          (activity table, or off-notice)
```

`s-grid gridTemplateColumns="repeat(auto-fit, minmax(200px, 1fr))" gap="base"` for the KPI row — 4 tiles at default admin width, 2×2 at narrow, 1-column on mobile. **Verify the prop name and value syntax against the live `GridProps`** at execution; if `auto-fit` is not accepted, fall back to `s-grid-item` with a responsive column prop.

**Banner precedence — render only the first that applies:**
1. Reconciliation incomplete / backfill running → info banner (Copy row B1 or B2)
2. Bypassed-order alert (≥1 `BYPASSED_ORDER` in last 30 days) → warning banner (Copy row B3)
3. Currency mismatch companies (D4-02) → info banner (Copy row B4)

(Reminders-off is NOT a banner — it lives inside the "Payment reminders" section as its empty/off state, Copy row R4. Stacked banners are noise; the section text carries it.)

### Responsive behavior

- No horizontal scroll on the page at any admin width. Tables use `s-table variant="auto"`, which stacks to the list variant below its breakpoint; numeric columns right-aligned via `format="currency"` (verify `HeaderFormat = base|currency|numeric`; use `currency` for money, `numeric` for counts/percentages).
- Long company names wrap, never truncate (Phase 3 rule).
- Feed description text wraps; timestamps stay on their own cell.
- KPI values up to 11 characters ("$1,234,567.00") must fit a 200px tile at 20px — verify on the dev store; if a value wraps, the tile grows, it never clips.

### Loading

SSR first paint (RR7 loader); no skeletons, no page spinners (Phase 1 rule). **One exception:** the setup-guide step 1 shows an inline `s-spinner size="small"` (verify prop) next to "Importing your order history…" while `readBackfillState(shop)?.status === "running"` — it is a genuine in-progress indicator for a background job, not a loading placeholder. The review prompt runs after mount and never blocks paint.

## Guided Setup Contract (DASH-03, D6-03)

**Where:** one `s-section heading="Set up Credit Guard"` at the **top of the dashboard**, directly under the banner slot, rendered while `Shop.onboardingDismissedAt == null`. After dismissal it is gone for good (no re-open affordance; BFS 4.2.2 #6).

**Anatomy:** `s-stack gap="base"` of three rows separated by `s-divider`. Each row: `s-stack direction="inline" gap="base" alignItems="center"` → `s-icon` (state) → `s-stack` (title `s-text type="strong"`, body `s-text color="subdued"`) → action `s-button`. Under the heading, right-aligned or as a first line: subdued **"{n} of 3 complete"**. When 3/3: the progress line reads **"All set"**, and the section's only button is **"Done"** (`variant="primary"`) which POSTs intent `dismiss-onboarding` → stamps `onboardingDismissedAt`, section disappears after revalidation, toast Copy row S9.

**Icon state map (verify names in live `IconType`):**

| Step state | Icon | Tone |
|-----------|------|------|
| Complete | `check-circle-filled` | `success` |
| Current (first incomplete) | `circle-dashed` | `neutral` |
| Needs attention (step 3 when rule disabled/unregistered) | `alert-circle` | `warning` |

**Button rule:** the current step's button is the page's single `variant="primary"`; completed and later steps' buttons are `variant="secondary"` (or hidden once complete — **hide** the button on completed steps except step 3, whose "Open checkout settings" link stays useful).

| Step | Title (exact) | Body (exact) | Complete when | Button (exact) → target |
|------|--------------|--------------|---------------|--------------------------|
| 1 | **"Review your balances"** | While backfill running: **"Importing your order history… {orderCount} orders and {companyCount} companies so far."** (+ inline spinner). When finished: **"{companyCount} companies with {orderCount} net-terms orders were imported. Check the balances look right before setting limits."** If `readBackfillState` is null or `failed`: **"Credit Guard couldn't finish importing your order history. Open the app again to retry; balances may be incomplete until then."** | `Shop.onboardingReviewedAt != null` (stamped by the button) | **"Looks right"** (POST intent `mark-reviewed`) — disabled while backfill is running. Secondary `s-link` **"Open companies"** → `/app/companies`. |
| 2 | **"Set your first credit limit"** | **"Companies stay observe-only until you set a limit. Start with the one company you most want to keep inside terms."** | `company.count({ creditLimit: { not: null } }) > 0` (derived, never stored) | **"Set a limit"** → `/app/companies` |
| 3 | live `active` + step 2 complete: **"Enforcement is on"** / otherwise **"Turn enforcement on"** | `active`: **"Companies over their credit limit or with overdue invoices can't complete a new net-terms order. You can turn this off any time in Shopify Settings → Checkout → Checkout rules."** · `disabled`: **"Credit Guard's checkout rule is switched off in Shopify Settings → Checkout → Checkout rules. Reload the app to let it set itself up."** | `Shop.validationGid != null` AND `readValidationConfig(shop).status === "active"` AND step 2 complete | `active`: **"Check checkout messages"** → `/app/settings` (secondary) · `disabled` / `unregistered`: **"Open settings"** → `/app/settings` (primary if current step). **No new mutation surface**; the existing ensure-step runs on every load, which is why "Reload the app" is the honest instruction. |

**Persistence semantics:**
- `onboardingReviewedAt` — set once by "Looks right"; never cleared.
- `onboardingDismissedAt` — set once by "Done"; never cleared. Guide visible iff null.
- Steps 2 and 3 re-derive every load (no writer discipline; cannot go stale). If a merchant later removes all limits, step 2 flips back to incomplete **only while the guide is still visible**; after dismissal nothing re-appears.
- "Done" is only offered at 3/3. There is **no skip**. BFS 4.2.2 wants onboarding removable once complete; a merchant who never completes it keeps a 3-row section, which is the intended nudge. ⚑ If the checker judges a skip mandatory, add a `variant="tertiary"` **"Hide setup"** that stamps `onboardingDismissedAt` with a confirmation-free click — not recommended.

**Step 2 deep link, step 3 pointer** are exactly as D6-03 requires. Nothing in the guide writes to Shopify.

## Review Prompt Contract (LNCH-02)

No UI of ours. The contract is timing and bookkeeping.

| Rule | Contract |
|------|----------|
| Eligibility (loader) | `reviewEligible = Shop.reviewPromptedAt == null AND (exists EnforcementEvent kind IN (BLOCK_STATE_ENTERED, BYPASSED_ORDER) OR exists ReminderLog status = SENT)` — computed shop-scoped in the dashboard loader only. |
| When | On the **next dashboard load** after a success moment, in a `useEffect` after mount — never mid-action, never on Companies/Settings, never after a button click, never from a toast. |
| Once | Call `shopify.reviews.request()` at most once per page load. Then POST intent `review-prompt-result` with `{ code }`. |
| Stamp | Server sets `reviewPromptedAt = now()` for every returned code **except** `recently-installed`, `already-open`, `open-in-progress` — codes under which Shopify never evaluated the request (an install younger than 24h, or a modal already up). Those three leave the column null so a later dashboard load asks again; every other code (`success`, `already-reviewed`, `annual-limit-reached`, `cooldown-period`, `merchant-ineligible`, `mobile-app`, `cancelled`) and a thrown error stamp it. Nagging stays impossible: Shopify enforces once/60 days, and the stamp lands on the first *evaluated* attempt. **Amendment 2026-08-22 (plan-check B-01, orchestrator-approved):** the earlier "record regardless of result code" rule would have stamped on `recently-installed`, and the guided setup drives the first BLOCK_STATE_ENTERED inside the 24h window — so most merchants would never have been asked (LNCH-02 / SC4). |
| Copy | None. Shopify owns the modal. No pre-prompt banner, no "rate us" text anywhere (policy 1.3.1). |
| Failure | If `reviews.request` throws or App Bridge is absent, swallow, still POST with `code: "error"`, still stamp. The dashboard must render identically whether or not the prompt fires. |

## Money & Date Formatting Rules

| Rule | Contract |
|------|----------|
| Money | Shared `createMoneyFormatter(currencyCode)` lifted to `app/lib/money.ts` (or similar) and imported by Companies + dashboard. Grouping separators always. Decimal strings in, strings out; never `parseFloat` arithmetic server-side — sums are Prisma `Decimal` aggregates or `Prisma.Decimal` adds. |
| Currency source | `resolveShopCurrency(shop)` (lift alongside the formatter). Null → decimal style, no symbol, and K1/K4 labels get no currency suffix (the number is still meaningful). |
| Dates (due dates) | `Intl.DateTimeFormat(undefined, { dateStyle: "medium" })` → "21 Aug 2026". Never a raw ISO string. Today → **"Today"**, tomorrow → **"Tomorrow"** in the "Due" column (only those two relative words). |
| Timestamps (feed, reminders "When") | Same `dateStyle: "medium"` + `timeStyle: "short"` → "21 Aug 2026, 09:14". No "3 hours ago" relative times (they go stale on a server-rendered page). |
| Overdue "Earliest due" | Date only; the badge says it is overdue, the cell must not editorialise ("3 days late" is a computation we do not show). |
| Counts | Plain integers, no abbreviations ("1,024" via `Intl.NumberFormat`, never "1k"). |
| Percent (if "Closest to limit" section is built) | Phase 3 rule verbatim. |
| Timezone | Browser-rendered where possible; SSR formats in UTC and the page states nothing about timezone. ⚑ Planner: if hydration mismatch warnings appear, format on the server with the shop's IANA timezone from the session/shop query and pass strings. |

## Accessibility

- Every `s-table` has an `s-table-header-row` with text headers (no icon-only headers).
- Badges always contain visible text; tone is supplementary.
- Banners use `s-banner` with `heading` so the semantic role/landmark comes from the component; never a styled `s-box` pretending to be a banner.
- Setup-step icons are decorative; the step title text carries the state ("Enforcement is on" / "Turn enforcement on"); completed steps additionally get `accessibilityLabel` on the icon if the catalog supports it, else a visually-hidden `s-text accessibilityVisibility="exclusive"` "Complete".
- Section header links have specific text ("View all companies"), never "View all".
- Focus order follows DOM order: banner → setup → KPIs → sections. No focus traps; the review modal is Shopify-owned.
- Tooltips use the existing `interestFor` pattern from Companies (hover + focus).
