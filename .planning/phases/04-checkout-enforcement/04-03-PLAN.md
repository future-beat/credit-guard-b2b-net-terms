## Phase Goal

**Goal (ROADMAP, verbatim):** Companies over their credit limit or overdue cannot place new net-terms orders, and no other checkout is ever affected.

## Branch & Process Discipline

- Execute on branch `phase-04-checkout-enforcement`; Wave 1 (04-01, 04-02) must be merged into the phase branch before this plan starts (it consumes the extension AND enforcement.server.ts).
- Registry releases (`shopify app deploy`) happen FROM THIS BRANCH — they are not gated on the git merge to main (user-mandated process). Railway also deploys from this branch (`railway up` ships the local directory).

## Locked Decisions

- **P4-L4 (planner lock, default message copy — the DEFAULT_MESSAGES single source):**
  - over_limit_message: "Your company has reached its credit limit with us. To place this order, please contact us or settle open invoices to free up available credit."
  - overdue_message: "Your account has overdue invoices. New orders on payment terms are paused until the balance is settled — please contact us to arrange payment."
  Both ≤ 250 chars, plain text. The Function (04-01) duplicates these strings by design (wasm cannot import server code); this file is the canonical home and 04-04's tests diff the two.
- **P4-L5 (planner lock, config shape):** validation metafield namespace `$app`, key `config_v1`, type json, value `{"v":1,"over_limit_message":"…","overdue_message":"…"}` — additive evolution only, same versioning law as credit_v1.
- **Research corrections binding here:** scope name `write_validations` (validationCreate page); `Query.validations` has no functionHandle filter — filter client-side; A3 fallback if `ValidationCreateInput.metafields` rejects the `$app` namespace: create bare, then metafieldsSet with ownerId = the new Validation GID; A4 (write-implies-read) is proven or disproven live by 04-05 EC-4 — if disproven, add the read scope in a follow-up lockstep commit.
